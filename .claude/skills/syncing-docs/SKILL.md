# Syncing docs

Make every living doc describe the app on `main` today. Leave dated records alone.

## Scope

| Living (edit) | Dated records (do not rewrite) |
| --- | --- |
| `README.md` | `docs/plans/*` |
| `docs/ROADMAP.md` | `docs/bugs/*` |
| `AGENTS.md`, `CLAUDE.md` | `docs/investigations/*` |
| `.claude/skills/*` (SKILL.md and scripts) | `docs/playtests/*`, `docs/sharing/*` |
| `docs/*/TEMPLATE.md` (paths and commands only) | |

Dated records were true on their date. Only fix broken links in them.

Also check user-visible strings that restate the same facts: the in-app help sheet (`sheet === 'help'` in `src/components/game.tsx`), level descriptions (`grep -rn LEVEL_NOTES src`), and every `title` and `description` in `src/app/layout.tsx` (metadata, openGraph, twitter). Report these; change them only in a separate code commit.

## Steps

1. **Get current code.** `git fetch`, then `git status -sb`. If local `main` is behind, fast-forward it (`git pull --ff-only`) when the tree is clean, or audit `origin/main` directly. Note the commit you audited and re-check it before reporting.
2. **List what shipped.** `gh pr list --state merged --limit 60 --json number,title,headRefName`. The roadmap's "Updated:" date is not a reliable anchor; feature PRs edit statuses without bumping it.
3. **Establish current behavior from code, not docs:** `src/lib/*.ts` (techniques, difficulty bands, preferences, home), `src/components/*.tsx` (screens, controls, keyboard shortcuts, Settings), `package.json` scripts, `.github/workflows/ci.yml`, `playwright.config.ts`.
4. **Audit each living doc line by line.** For every claim, find the code that confirms or contradicts it. Check every path, script name, CSS class, and file referenced exists (`ls`, `grep`).
5. **Audit for missing coverage.** For every merged `feat` PR, confirm README describes the player-facing behavior and ROADMAP marks it shipped. Adding a bullet or section to an existing doc is in scope.
6. **Check consistency between docs**: README vs ROADMAP shipped status; keyboard shortcuts in README vs `game.tsx` vs the help sheet; CI steps in README vs ROADMAP vs `ci.yml`; AGENTS.md vs the skills that expand it (screenshots, design directions). AGENTS.md should point to a skill rather than repeat it.
7. **Roadmap specifics:** statuses that name a branch (`On feat/...`) become PR links, matched by `headRefName` from step 2. In the Sequence table, mark a row "(shipped)" when its first useful release shipped, and "(partly shipped: <what remains>)" otherwise. Bump "Updated:".
8. **Edit with targeted line changes**, not rewrites. Keep each doc's structure and voice. The Next.js block at the bottom of AGENTS.md is generated by `next dev`; leave it.
9. **Verify:** `grep` each changed path or command exists; re-read changed sections.

## Output

A table of changes (file:line, old claim, new claim, source that proves it), then a short list of things found but not changed (code strings, dated-doc links, open questions for Sean).

## Out of scope

- Rewriting dated records to match today.
- Changing app code or copy (report it instead).
- Adding new roadmap items or reprioritizing (use recording-playtest-notes for new items).
- Creating new doc files.
- Cleaning up `.worktrees/` or branches; list stale ones for Sean instead.
